桌面宠物形态的多 harness agent 壳 — 架构分层、概念双轴、目标人群与 GTM 策略（2026-09-03 整理）

① 多 harness 统一壳：什么通用，什么各家自有架构分层

通用性分两层；MCP 是跨 harness 的最大公约数。SDK / 桌面端 / 私有扩展不通用，靠契约层对 UI 透明。

② Harness 轴 × Model 轴：两个独立维度概念澄清

壳统一的是竖轴（Harness），不是横轴（Model）。换模型通常在单 harness 内即可，不靠壳。

③ 两层产品模型 × 两类人群定位

伴侣层（宠物+面板）对所有人通用；统一层（多 harness 切换）是增值层，只在用多家时触发。

目标人群与卖点矩阵

人群特征痛点我们的主张交付层态度
A 统一派 同时用 codex / claude / pi，天天切窗 切软件、丢上下文、审批散落 “一个壳，装下你所有的 agent” 伴侣层 + 统一层 强烈建议体验
B 宠物派 只用 Codex（或任一），只换模型 无“切软件”痛，但想要更好体验 “你最爱的 Codex 不动，多一只会陪你、会喊你审批的宠物” 伴侣层（宠物 + 面板） 来撸宠物
GTM 策略：首屏先讲 B（宠物楔子，对所有人成立），再讲 A（统一层，对少数人多成立）。 统一层只对 A 共鸣且 A 是少数；若首屏只喊“统一所有 harness”，B 会直接走人。 两个卖点当前都依赖 C3（Codex adapter）：A 需 ≥2 个真 adapter 才能“切不换窗”，B 需宠物能骑在 Codex 上跑。

对外话术的硬边界（避免小白误解）

  • 宠物不是“盖在外部 Codex Desktop 上的浮层”。当前架构中壳是 host，harness 由壳启动，宠物吃的是契约事件流。所以 B 的真实含义是：“用我们的壳启动 Codex（引擎/账号/计费不变），白赚一只宠物”，不是同时开两个东西。
  • 壳不伪造能力。Codex 在壳里跑，底层仍是 Codex 引擎/模型/账号；答案质量不增不减，壳只是前端 Wrapper + 伴侣层。
  • 换模型走横轴。若 B 只想换 DeepSeek/GLM/GPT，靠 Codex 自身模型网关即可，本壳不解决、也不该解决模型切换。
