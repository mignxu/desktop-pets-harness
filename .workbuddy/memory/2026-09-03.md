### 讨论结论（已锁定的产品决策）
- **产品 = 两层**：① 伴侣层（宠物+面板，harness 无关，通用）② 统一层（多 harness 切换不换窗，增值层，仅用多家时触发）。
- **两类目标人群**：
  - A 多 harness 统一派（同时用 codex/claude/pi，天天切窗）→ 主张"一个壳装下所有 agent"，强烈建议体验（交付两层）。
  - B 单 harness 宠物派（只用 Codex/任一，只换模型）→ 主张"你最爱的 Codex 不动，多一只会陪你、会喊你审批的宠物"，来撸宠物就好（仅交付伴侣层）。
- **GTM 策略**：首屏先讲 B（宠物楔子，对所有人成立）后讲 A（统一层，对少数人多成立）；若只喊"统一所有 harness"会劝退 B。
- **关键约束（对外话术硬边界）**：宠物不是盖在外部 Codex Desktop 上的浮层——当前架构壳是 host，harness 由壳启动，宠物吃契约事件流。B 的真实含义是"用我们的壳启动 Codex（引擎/账号/计费不变），白赚一只宠物"。壳不伪造能力。
- **C3 是 GTM 闸门**：A（需 ≥2 真 adapter 才能切不换窗）与 B（需宠物能骑在 Codex 上跑）两个卖点当前都依赖 Codex adapter。

### 概念澄清（用户带入小白视角验证）
- Harness 轴（壳统一）vs Model 轴（换模型不靠壳）是两个独立维度。换模型通常在单 harness 内用模型网关解决，不需本壳。
- 多数"换 harness"本质是想换底层模型家族（Codex→GPT 系、Claude Code→Claude）；若单 harness 网关能拿到所需模型，则换 harness 边际收益很小。
